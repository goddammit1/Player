# Фаза 4 — Рассинхрон путей тестов (зафиксировано)

Раздел REFACTORING_PLAN.md **4.3** предлагает устранить рассинхрон путей
live-тестов переносом в `test/live/` [ново].

## Что подтверждено (факт)

Live-файлы (`@Tags(['live'])`) лежат не единообразно:

| Файл | Путь | Тег |
|------|------|-----|
| `youtube_source_test.dart` | `test/sources/` | `@Tags(['live'])` |
| `soundcloud_source_test.dart` | `test/` (корень) | `@Tags(['live'])` |
| `muzmo_source_test.dart` | `test/` (корень) | `@Tags(['live'])` |
| `muzmo_artwork_integration_test.dart` | `test/` (корень) | `@Tags(['live'])` |

Директории `test/live/` на данный момент не существует.

## Решение и обоснование

**Живые файлы НЕ перемещены.** Вместо этого рассинхрон зафиксирован данным
документом. Причина: инструкция по Фазе 4 явно запрещает изменять live-тесты
(`@Tags(['live'])`) и запускать их. Перемещение файлов — это изменение
структуры тестов, а перенос, даже чисто механический, повышает риск
реестрочной ошибки в прогоне live / обычном прогоне без выигрыша в покрытии
(они по-прежнему остаются тегами `live` и не входят в обычный не-live прогон).

План 4.3 помечен с формулировкой «перенос в `test/live/` [ново]», а общий
риск-блок (п. 8) отдельно предупреждает про widget-тесты в headless. Требования
пользователя имеют приоритет над общими инструкциями плана: live-тесты
запрещено трогать/перезапускать в рамках этой фазы.

## Что покрыто вместо перемещения

- Не-live тесты для тех же источников уже существуют в `test/sources/`
  (в обычном прогоне):
  - `muzmo_fixture_test.dart` — фикстурные тесты Muzmo (без сети).
  - `soundcloud_fixture_test.dart` — фикстурные тесты SoundCloud (без сети;
    покрывает `lib/sources/soundcloud_parser.dart` через
    `SoundCloudSource.parseTracks`).
  - `youtube_source_unit_test.dart` — unit-тесты YoutubeSource (без сети;
    вынесены из `youtube_source_test.dart`, чтобы выполняться в обычном прогоне).
- Live-файлы корня и `test/sources/` оставлены как есть; каждый прогон обычных
  тестов их исключает через `dart_test.yaml` (`tags.live.skip`).

## Остаточный риск

`flutter analyze` чист; обычный (не-live) прогон зелёный. Единственное,
что остаётся открытым к будущей параллельной консолидации, — перенос самих
live-файлов в `test/live/` (idiom плана), выполнимый отдельной задачей вне
Фазы 4, когда политика «не трогать live» будет снята.
